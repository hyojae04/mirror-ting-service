# UX 라이팅 기준 및 변경 기록

2026-10-31. 처음에는 검토 후보로만 정리했고, 이후 사용자가 서비스 안내·버튼 명칭·오류 안내·용어 네 항목의 변경과 캡처 비교를 요청해 적용했다. 이전에 별도로 반영한 회색 토큰 변경과 이번 문구 변경은 별개다.

## 채택한 기준

- 명시적 사용자 요청 → 이 문서의 기능 근거 → 주요 화면의 정확한 표현 순서로 적용한다. 빈도가 높아도 기능을 잘못 설명하는 문구는 기준으로 삼지 않는다.
- 서비스는 Mirror-Ting, 연습 종류는 ‘면접’, ‘직장 대화’로 표기한다. 설문으로 만드는 결과는 ‘시나리오’, 그 과정은 ‘시나리오 설계’다. ‘대화 연습·시뮬레이션’은 실제 대화 단계이며 현재 공개 체험에서는 실행하지 않는다. 4-Fit 소개는 미리보기로 구분한다.
- 일반 안내는 해요체, 제목과 버튼은 명칭 또는 짧은 행동 표현을 쓴다. 기존 브랜드 제목 ‘먼저 연습해요’, ‘먼저 연습하세요’의 맥락은 유지한다. 사용자 작성 내용·AI 대사·인용문은 UI 안내와 분리한다.
- 홈 진입 버튼은 사용자 지정 문구 ‘연습해보기’를 유지한다. 사용 방법의 버튼도 같은 설문으로 가므로 같은 문구를 쓴다. 홈으로 이동하는 버튼은 ‘홈에서 연습 준비하기’, 최종 생성 요청은 ‘시나리오 만들기’, 응답 후에는 ‘시나리오가 준비됐어요.’로 구분한다. 저장·제출·완료·취소·닫기의 의미를 섞지 않는다.
- 오류는 문제 → 다음 행동 순서로 쓴다. 확인하지 못한 원인을 연결 문제나 입력 잘못으로 단정하지 않는다. 원인이 확인되는 필드 오류는 구체적인 입력 안내를 유지한다. 답변은 현재 화면 상태에서만 유지되므로 영구 저장을 보장하지 않는다.
- 빈 화면은 상태 → 가능한 다음 행동, 완료는 완료된 일 → 필요한 다음 행동 순서로 쓴다. 삭제 안내는 대상·영향·복구 가능 여부를 구현 근거로 설명해야 한다. 이번 범위에는 삭제 동작이 없다.
- 화면 표시 용어는 ‘사용 방법’, ‘연습 기록’, ‘직장 대화’로 쓴다. 코드 식별자·API 키·저장 값은 그대로 유지한다. 턴 수의 설명 단위는 ‘턴’으로 맞춘다. 카운터 `n / 2,000`, 단계 `01 / 04`, 저장된 날짜 문자열은 각 역할을 유지한다. 날짜 정보나 시간대를 추정하지 않는다.
- 저장 여부·요금·권한·복구 가능 여부·처리 시간은 실제 구현을 근거로 쓴다. 요금·동의 고지·약관·민감한 조건은 임의로 축약하지 않는다.

## 전후 캡처와 검증

이전에 만든 before 캡처는 직전 배포 커밋 `be16dbc`의 배포 아카이브를 렌더링했다. after 캡처는 수정한 실제 앱을 같은 Chrome, 1200×900, DPR 2, 동작 줄이기 설정으로 렌더링했다. 문구를 이미지 위에 합성하지 않았다.

- 서비스 소개: 실제 소개 화면의 설명과 홈 이동 버튼을 캡처했다.
- 버튼: 사용 방법 상세 하단의 실제 버튼을 캡처했다. 변경 후 설문 진입을 확인했다.
- 오류: 테스트에서만 요청을 중단해 실제 오류 UI를 띄웠다. AI 제공자의 실제 장애를 재현했다고 주장하지 않는다. 오류 후 작성한 답변이 유지되는지 확인했다.
- 용어: 실제 연습 기록 필터에서 직장 대화를 선택해 변경 전후를 캡처했다. 표시 문자열만 바꿨다.

추가 검증: 320px 모바일에서 소개·가이드·기록·오류 화면의 표시와 이동을 확인했고, TypeScript 검사 및 서버 테스트 3개가 통과했다.

레이아웃·색상·모델·temperature·API 계약·동의 내용·실제 저장 로직은 이번에 변경하지 않았다. 실제 저장 기록 데이터의 상태 판정, 실 사용자 반응, VoiceOver·Safari는 별도 확인 대상이다. 이전 후보 중 날짜 미상 표현 등 이번 네 항목과 직접 관련 없는 문구는 보류했다.

**Approve — 적용한 네 항목과 위 검토 범위에 대한 판정이다.** 미구현 로그인·실제 시뮬레이션·결제 기능의 구현 완료를 의미하지 않는다.

## 추가 일관성 점검 및 캡처 정리

사용자 요청으로 프로젝트 캡처 이미지 30개, 임시 캡처 파일 155개와 비교 HTML을 삭제했다. 삭제된 캡처 링크도 문서에서 제거했다. 제품용 사진·아이콘·생성 시안은 캡처가 아니므로 삭제 대상에 포함하지 않았다. 현재 소스의 삭제이며 Git 과거 커밋을 재작성하지 않았다.

추가 점검에서 확인한 사항:

- 홈 푸터의 ‘연습 시작하기 / 면접 연습하기’는 위의 진입 버튼으로 스크롤하므로 ‘연습 준비로 이동’으로 바꿨다. ‘연습 종류 고르기’는 실제 홈 이동에 맞춰 ‘홈으로 돌아가기’로 바꿨다. 남은 화살표 장식도 제거했다.
- 브라우저 제목 ‘사이트 소개 / 결과 및 기록’은 메뉴와 같은 ‘서비스 소개 / 연습 기록’으로 맞췄다.
- 날짜가 없는 같은 상태를 ‘날짜 정보 없음’으로 맞추고 개수는 ‘n개 기록’으로 표기했다.
- 설문과 사용 방법에 남은 동일 값의 흰색·회색·링크색·기본 글자 크기를 기존 토큰 참조로 바꿨다. 대비를 위해 별도로 정한 오류색 같은 고유 값은 임의로 바꾸지 않았다.
- `StudioIntro.jsx`, `WorkspaceNavigation.jsx`는 현재 import 사용처가 없는 예전 컴포넌트라 공개 화면의 불일치로 판단해 수정하지 않았다. 사용자 입력·AI 대사·API 계약·저장 상태 판정도 바꾸지 않았다.

이번 추가 검증은 캡처를 저장하지 않고 진행했다. 설문 6개 화면 크기 × 5개 상태, 사용 방법 6개 화면 크기 × 3개 상태, 1440px·320px 푸터 스크롤/포커스·홈 이동·화면 제목, 타입 검사 및 서버 테스트 3개가 통과했다. 각 브라우저 테스트에 포함된 접근성 검사에서도 위반이 없었다. QA 폴더의 캡처 이미지 잔여 개수는 0개다.

## 메인 페이지 제목·버튼 크기와 줄 수

사용자 요청으로 메인 페이지의 기존 제목 위계에 공통 배율 1.06을 적용했다. 히어로 → 4-Fit 섹션 제목 → 스토리 제목 → 상세 제목의 크기 관계는 유지한다. 메인 알약 버튼은 PC 높이 56px·글자 16px, 모바일 높이 52px·글자 15px로 키웠다. 다른 페이지의 버튼이나 헤더 메뉴 크기는 바꾸지 않았다.

제목은 두 줄 이내, 주요 부연 문구는 한 줄로 읽히도록 홈·스토리·4-Fit·하단 진입 영역의 문구를 간결하게 다듬었다. 예: ‘미러팅과 먼저 연습하세요.’ → ‘미러팅과 연습해요.’, ‘내 상황에 맞는 대화를 골라보세요. AI가 연습할 장면을 준비해요.’ → ‘내 상황에 맞는 AI 시나리오를 만들어요.’ 실제 설계 흐름과 서비스 의미는 유지한다. 말줄임·줄 수 제한·overflow 숨김으로 텍스트를 삭제하지 않고 자연 줄바꿈을 유지해 확대된 글자도 읽을 수 있게 했다.

당시 320·360·390·768·1024·1280·1440px의 반복 측정에서 주요 제목 154개는 최대 두 줄, 부연 문구 140개는 한 줄이었다. 추가 점검에서 외부 주소의 service 쿼리가 iframe 내부로 전달되지 않아 실제로는 기본 홈을 반복 측정한 점을 확인했다. 아래 복원 검증에서는 내부 앱의 실제 서비스 모드 주소로 각각 진입해 확인했다.

## 직전 문구 축약 복원

이후 사용자 요청에 따라 파란색 스토리 섹션까지 포함해 직전 제목·부연 문구 축약을 모두 되돌렸다. `f192022` 버전의 홈·스토리·4-Fit·하단 진입 문구와 모바일 히어로 줄바꿈을 복원했다. 그 이전의 서비스 범위 안내·버튼 동작에 맞춘 명칭·오류 안내 개선은 유지한다.

확대한 제목 위계와 알약 버튼 크기는 유지한다. 복원한 긴 설명은 좁은 화면에서 자연스럽게 줄바꿈한다. 따라서 위의 ‘부연 문구 한 줄’ 검증은 이전 축약 버전의 기록이며 현재 복원 버전의 제약이 아니다. 로그인·회원가입 그룹은 기존 간격 토큰으로 PC에서 24px, 모바일에서 8px 왼쪽에 여유를 두었다. 캡처 파일은 생성하지 않는다.

복원 검증: 내부 `/original/index.html?service=interview`와 `?service=workplace`를 직접 열어 320·390·768·1024·1440px에서 원문·버튼 크기·로그인 안내·설문 진입·헤더 겹침을 확인했다. 복원 대상 JSX 5개 파일은 축약 전 커밋과 바이트가 일치한다. 일반 스크롤 18단계에서도 내용 잘림이 없었고 타입 검사도 통과했다.

## 파란색 스토리 섹션만 줄 수 맞춤

최신 사용자 요청으로 파란색 스토리의 제목은 두 줄, 부연 문구는 한 줄에 들어오도록 그 섹션 문구만 다시 다듬었다. 히어로·4-Fit·하단 진입 문구는 복원한 그대로 유지한다. 예: ‘무슨 말을 할지 망설이는 / 첫 회식도.’ → ‘무슨 말을 꺼낼지 / 망설이는 첫 회식도.’, 마지막 강조 제목은 ‘미러팅과 연습해요.’로 줄였다.

밝은 배경의 메인 부연 문구는 기존 `--color-ash`(#707070) 참조가 적용된 것을 확인했다. 파란색 배경의 설명은 기존 밝은 회색 `--color-pebble`(#e2e2e5)을 사용해 푸른 기가 있는 별도 색상값을 제거했다. 실제 토큰을 임시 변경했을 때 각 설명 색이 함께 갱신되는지도 검증했다. 제목과 강조색은 유지한다.

실제 내부 주소에서 면접·직장 대화 각각 320·360·390·768·1024·1280·1440px를 확인했다. 네 스토리 제목은 모두 정확히 두 줄, 설명은 모두 한 줄이며 가로 넘침이 없었다. 일반 스크롤 18단계에서 잘림이 없고 설문 진입·타입 검사도 통과했다. 이번 검증에서도 캡처 이미지를 저장하지 않았다.

## 메인 알약 버튼 축소

사용자 요청으로 메인 페이지의 알약 버튼 높이와 글자 크기를 PC·모바일 모두 44px·14px로 맞췄다. 상단·하단의 ‘연습해보기 / 사용 방법’ 쌍은 폭도 120px로 통일했다. 파란색 섹션의 긴 버튼은 같은 높이·글자 크기를 적용하고 문구 길이에 맞는 폭을 유지한다. 다른 페이지의 버튼·헤더·메인 제목과 설명은 바꾸지 않았다. 면접·직장 대화의 320·390·1024·1440px에서 버튼 5개의 크기·잘림·포커스 이동·사용 방법 및 설문 진입과 타입 검사를 확인했고 캡처는 저장하지 않았다.

## 메인 버튼 중간 크기 조정

이후 사용자 요청으로 축소 전과 직전 크기 사이인 높이 48px·글자 15px로 조정했다. 상단·하단의 두 주요 버튼 폭은 128px로 맞췄고 긴 스토리 버튼은 문구에 맞는 폭을 유지한다. 대체 구조는 레퍼런스로 제안하며 아직 적용하지 않았다. 면접·직장 대화의 320·390·1024·1440px에서 버튼 크기·잘림·포커스와 사용 방법·설문 이동을 검증했다. 캡처는 저장하지 않았다.
